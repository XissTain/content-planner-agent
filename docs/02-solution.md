# 02 · 方案设计

## 动态决策循环

```text
校验请求 → 读取 SQLite checkpoint → 刷新业务时钟和已有测算
                                      ↓
                            GPT 选择一个结构化动作
                                      ↓
                     Python 校验工具参数、依赖和硬约束
                                      ↓
                         执行工具，保存实际观察与状态
                                      ↓
                  将实际观察交给下一轮 GPT，或依据状态结束
```

真实模式每轮执行 `codex exec`。输入为工具定义、当前请求、成功成果和历史实际返回；输出为 `tool`、`arguments_json`、一句公开行动依据。运行器不预先决定超预算要换哪组服务，也不内置遇到失败就自动重试的分支。

单轮只有一个动作，每次运行最多 12 个动作。模型没有权限修改预算、截止时间和必需素材，不能用 finish 声称成功；只有实际方案已写入数据库才 completed。超时、模型错误、上限和模型主动停止分开记录 stop_reason。

## 用户质量偏好

候选人明确选择“优先保留创意脚本，先简化制作”，对应 `replan_priority=preserve_script`。初始 premium/polished 成本 12，预算 10；若 premium/simple 的测算符合硬约束，则保留脚本，采用成本 10 的方案。

对照 `preserve_production` 时，先保留 polished 制作、换脚本服务。偏好是软约束，预算和截止时间是硬约束；原路线经测算不可行时才放宽偏好。不同输入引起的变化应由真实 Trace 验证，不能仅依赖提示词声明。

## 工具与保护

| 工具 | 输入 | 返回与依赖 |
|---|---|---|
| search_assets | query | 合成素材、来源、事实；无结果可由模型改写查询或要求补充 |
| estimate_plan | asset_ids、script_service、production | 分项费用、总价、串行工时、预计结束、预算与时间缺口 |
| generate_script | candidate_id | 仅接受可行测算；本地模板只使用资料中的事实，带来源 ID |
| save_plan | candidate_id | 可行测算和已成功脚本均存在，才实际写入 SQLite |
| finish | needs_input/incomplete、message | 明确缺信息或无法继续；不接受 completed |

业务工具可以 Mock，模型决策不能用固定规则冒充。因此 MockModel 名称、公开依据、输出模式和 evidence_modes 均明确标识；不能把其动作当作真实模型能力证据。

工具参数、资料成本和分钟数均由程序校验。成本/分钟不接受负数或布尔值。真实 SQLite 写入异常也会成为失败观察，不能仅靠“故障注入”分支演示失败处理。

## 临时故障、服务不可用与续跑

临时故障返回 retryable=true，GPT 可以有限重试、替代或停止。服务故障可按 `generate_script@premium` 注入，返回 retryable=false；GPT 应换脚本服务并重新测算，或停止。

故障注入配置只用于测试，不能进入模型观察。成功素材、全部测算、脚本和每次调用的成败保存在 checkpoint。保存失败不清空脚本，进程重启后仍可复用。离线替身的重试限制按本次运行统计，避免上次重试耗尽后永久无法续跑。

最新一次失败不能被历史成功掩盖：steps 展示最新调用状态和成功次数；preserved_results 单独保存历史成功成果。

## 幂等与状态

`runs.id` 和 `plans.request_id` 唯一。请求内容和整份资料表共同生成 fingerprint；同 ID、同输入重复执行复用同一方案，0 次新模型动作。同 ID 换输入或资料表则拒绝，要求新请求 ID。

每个动作后写 checkpoint。方案保存后、checkpoint 更新前崩溃，下一次优先查真实方案表恢复。脚本缓存按素材和脚本服务标识；只更换制作方式可复用脚本。

面向本地串行任务，不宣称多进程同时执行同一请求的外部副作用保证。验收并行只用于不同请求、不同数据库。

## 时钟和费用边界

提供 start_at 时使用固定模拟时钟，保证样例可复现。不提供时使用真实时钟，每次模型决策前刷新已有测算，工具执行前再次校验；模型等待期间过期，也不能保存。已保存的历史方案重复读取不重新排期。

估价取自版本化合成表，用整数模拟单位计算素材、脚本和制作的逐项和，不是实际付费账本，不计入模型费用。耗时是串行整份方案的保守估计，不代表真实内容已经制作；production 的状态明确为 planned。

## 模型接入与可审计证据

Codex CLI 只作为推理与登录入口。应用传递显式目标型号和低推理预算，使用空临时目录、只读沙箱、忽略用户配置，移除桌面任务线程和工具管道环境，保留登录目录与公开认证环境变量；关闭不需要的 CLI 工具功能。不会读取、复制或提交 auth.json。

每步记录实际公开输入、动作、参数、返回、时间、耗时、使用量和输入 SHA-256；不收集内部推理过程。输出清单包括实际请求、资料表和当前应用源码哈希。独立核对器检查文件完整性、前一步实际结果是否进入下一步输入，并从资料表复算最终费用、工时、来源与依赖。哈希不构成模型服务端签名。

原生 Python 循环承担调度和边界，SQLite 承担本地持久化，Codex 承担模型推理。无 Agent 框架、UI、线上部署或多 Agent，符合题面允许的核心交付范围。
