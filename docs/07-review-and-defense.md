# 07 · 个人复查与答辩

本页根据代码与实际设计整理说明，供候选人理解后自行表达。不能仅因为本页存在，就声称候选人已经亲自复跑或掌握全部实现。

## 一分钟项目说明稿

这个项目帮助运营在预算和截止时间内生成内容活动方案。我确认的业务取舍是预算不足时优先保留创意脚本，先简化制作。实现由 Codex 辅助完成：GPT 每轮选择业务工具，Python 执行并把实际结果交给下一轮模型；预算、时钟和保存条件由程序校验。项目还处理临时故障、服务替代、幂等和跨进程续跑。真实模型与离线测试分别记录，不把 Mock 当作模型能力证明。

这里的“我确认”仅指对话中实际完成的业务决定，不代表代码为候选人独立编写。

## 应当能够解释的设计

### 1. 为什么是 Agent，而非固定串行调用？

[Agent.run](../src/content_planner/agent.py) 每轮调用 model.decide，根据模型返回的工具名和参数执行一个动作，再把真实结果写入历史。模型可以再次测算、换服务、重试或停止。运行器不包含“预算失败一定换 standard”或“错误就自动重试”的固定业务分支。

[MockModel](../src/content_planner/models.py) 确实有预设分支，但它是离线替身并被明确标记。证明动态决策必须查看真实模式的 Trace 和模型输入。

### 2. 为什么没有用 LangGraph 等框架？

本题需要单动作循环、工具依赖、上限和 checkpoint，Python 与 SQLite 足以表达。题面明确框架名称不加分。选择原生实现减少评审安装成本，代价是需要自己维护状态与错误边界。

### 3. 为什么不是直接选最便宜的方案？

预算是上限，质量偏好决定可行方案间的取舍。候选人选择保留创意脚本后，素材 2＋premium 6＋simple 2=10 符合需求。素材 2＋standard 2＋polished 4=8 也可行，但降低了候选人希望优先保留的脚本服务。相反偏好的对照用例应产生不同结果。

### 4. 为什么费用由程序算？

模型选择组合，estimate_plan 读取实际资料表逐项加总。生成与保存再次检查可行性，因此即使模型尝试跳过预算或依赖，也不能保存。独立核对器还从资料表重新计算最终费用，而不只信任输出里的 fits_budget=true。

### 5. 失败和续跑怎样实现？

成功素材、测算、脚本和历史调用持久化到 SQLite。保存失败后保留脚本，新进程读取状态，再由模型选择下一步。验收检查两个进程 PID 不同、脚本 ID 未变和第二段只有保存动作。

### 6. 怎样防止重复提交？

请求 ID 唯一，输入和资料表共同生成 fingerprint。重复的同一请求读取既存方案，0 次新模型或业务动作。同 ID 更改参数或成本表会拒绝复用。此保证针对本地串行请求，不宣称分布式 exactly-once。

### 7. 模型超时与工具失败有什么不同？

模型超时还没有取得下一动作；返回 incomplete/model_error，并保留成果。工具失败是已经取得模型动作、实际执行后返回错误；该观察会交给下一轮模型。验收不可把模型超时当作“预算无法满足”的正确业务终止。

### 8. 如何验证截止时间？

模拟输入提供 start_at，方便复现。真实输入不提供时，每轮和保存前刷新现实时间。模型响应等待造成计划过期，也会被工具阻断。耗时仍是整份方案的保守串行估计，不是真实制作排程。

### 9. 你个人做了什么？

目前可如实回答：提供题面与约束、确定通过 Codex/GPT 验证、要求逐项审查，以及确认“先保留脚本质量”的业务规则。代码、计算、测试与文档由 AI 辅助完成。尚未亲自运行或修改的部分，不应说成已经完成。

## 建议亲自复跑的一条命令

在项目目录执行：

```bash
python3 run.py examples/inputs/user-priority.json --mode mock --db .runtime/personal.sqlite3 --out .runtime/personal
```

核对 `.runtime/personal/result.md`：总价应为 10，脚本 premium，制作 simple，活动尚未实际执行。查看 trace.md，确认先测算 12，再测算 10，最后实际保存。不要把这次离线复跑当作真实模型验证。

实际完成后，才向 contributions.json 和 AI 使用记录补充自己的命令、观察、时间及修改；不要预填。
